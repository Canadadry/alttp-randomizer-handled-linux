# check-e2e

**Argument**: the game's test directory, `tests/alttp` (the default, when none is given) or `tests/ladx`. Written `<game>` below. Every command runs from the repository's root.

In this repository `e2e` is part of `make check`, which `check-net` runs after each PRD and after each `skill:` step: per-PRD checking is `check-net`'s job, not this skill's. This skill is run only by plan-pilot, for a `skill: check-e2e` step of the plan, as a dedicated pass over the whole case list.

A red case is always a bug in the C port, or, for LADX, in a ROM-derived artifact (see "Where the fix goes"). Never run a golden generator to get green, never edit a file of `<game>/cases/` or `<game>/combos/`.

Every e2e bug leaves behind a unit test that catches it in `make -C <game> test`. That is the point: the next time, the dev loop catches it in seconds instead of the net catching it later.

## The games

**ALttP (`tests/alttp`).** `make -C tests/alttp test` is the dev loop. `make -C tests/alttp e2e` is every case of `tests/alttp/cases/` generated by the C port and diffed against what the VT oracle wrote: the RNG trace, `attempts`, `spoiler.json` and, for a claim `<case> all <group>`, the ROM write log `rom_writes.txt` up to the last write of that group (`tests/alttp/write_groups.txt` names the groups, in `writeToRom`'s order). `make -C tests/alttp e2e-combos` does the same for `tests/alttp/combos/` with `tests/alttp/combo_claims.txt`. Golden generator: `tests/alttp/oracle/gen_golden.sh`.

**LADX (`tests/ladx`).** `make -C tests/ladx test` is the dev loop. `make -C tests/ladx e2e` first compares C's projection of every golden write log with `write_log.py`'s (`PROJECTION` lines), then runs `ladx_gen --tables data/ladx` on every case of `tests/ladx/cases/` and diffs, per `tests/ladx/claims.txt`: `run.txt` at the claimed stage (placement, world setup, pool and the fill's RNG trace), each claimed group's `trace` lines, and each `group`'s `rom_writes.txt` projection. `make -C tests/ladx e2e-combos` does the same on `tests/ladx/combos/`. With the ROM (`tmp/ladx/base.gbc`, fetched only by `tests/ladx/oracle/fetch_rom.sh`), `make -C tests/ladx e2e-rom` compares C's KS span list with the oracle's (`KS DIFFERENT` lines), then claims every `group` and `rom-group`, the spoiler and the net effect on every case and combo. Contracts: `tests/ladx/README.md`, "E2E driver and claims" and "ROM-present e2e". Golden generator: `tests/ladx/oracle/gen_golden.sh`.

## ROM safety (LADX)

- Never print a ROM byte. With the ROM present, C's outputs (`tmp/ladx-e2e-rom/runs/…`, or any `ladx_gen --rom` output dir) may hold ROM bytes as literals when C is wrong: compare them through the driver, by digest, or by offset and length only; never `cat`, `diff` or `head` them. A bug report under `e2e-rom` holds only the driver's own (redacted) lines.
- Never write or echo `LADX_ROM_URL`, nor put it in a report or a commit message.
- A `setup:` line (no ROM, a wrong ROM, a missing tool) is a setup problem, never a failure for `fix-bug`.

## Rule #1 — never wait on the human

No one answers during this loop. A `QUESTION:` from any sub-agent goes to a fresh `guideline` agent, never to the user. The only way back to the human is the stop after 3 failed attempts (step 5).

## Rule #2 — you are the human at fix-bug's commit gate

`fix-bug` stops once, at its `git-commit` proposal, for a human go-ahead. Here, you give or refuse it, after running the checks of step 4 yourself. Never accept on the strength of an agent's report.

## Loop

### 1. Run the net — the first commands

```sh
mkdir -p tmp/check-e2e && rm -f tmp/check-e2e/*.txt
make -C <game> e2e        > tmp/check-e2e/e2e.txt 2>&1
make -C <game> e2e-combos > tmp/check-e2e/e2e-combos.txt 2>&1
# LADX only, when tmp/ladx/base.gbc exists:
make -C tests/ladx e2e-rom > tmp/check-e2e/e2e-rom.txt 2>&1
python3 .claude/skills/check-e2e/scripts/rank_e2e.py <game> tmp/check-e2e/*.txt
```

Name the files exactly after their targets: the ranker takes the run's name from the file name and orders the runs `e2e`, `e2e-combos`, `e2e-rom` whatever the argument order. The ranker's exit code:

- `0` → green. For LADX without the ROM, say in the report that `e2e-rom` did not run. Report `E2E-GREEN:` with the list of `fix:` commits made during this run, and stop.
- `3` → only `SETUP` lines: set the environment up (`CLAUDE.md` § Checks), then run step 1 again. Never hand a setup line to `fix-bug`.
- `1` → failures, ranked; go to step 2. `SETUP` lines printed alongside are handled as for `3` before the next run.
- `2` → a usage error of yours.

`make` exits 2 whenever a target fails; that is expected here, only the ranker's exit code counts. `e2e-rom` runs the cases, then the combos only when every case passed: its combos are ranked on a later loop.

### 2. Take the top failure

One failure = one `DIVERGENT <case>` block, or one target-level failure (the lines of a run that are not a case verdict). The ranker prints them all in rank order, then the top one's block verbatim (`TOP …`) and its single-case command (`REPRO …`). Take the top one; handle it alone; the others wait for the next run, since a fix often repairs more than one. The ranking (the ranker's contract, below) puts the cheapest to diagnose first.

### 3. Invoke fix-bug on it
Invoke the `fix-bug` skill in place. Its argument is a bug report you write, containing:

- **Game**: `<game>`.
- **Symptom**, verbatim: the `TOP` block, which is the driver's output for this failure, nothing paraphrased.
- **Reproduction**: the `REPRO` command, which replays the case alone. Then:
  - ALttP, a seed-level failure: the diff of the case's VT trace against the C trace, starting at the first draw that differs.
  - ALttP, a write-log failure: the first differing `rom_writes.txt` line, golden and C, verbatim from the detail (`<address> <bytes> <Rom method>`, `<end>` when absent), with its group and write number; for a short or missing log, the golden's first missing line (`sed -n '<k+1>p'` of the golden's `rom_writes.txt`). The address is a PC offset, the method is the VT setter that wrote it.
  - LADX, a seed-level failure (a `run.txt` section): the first differing line of the projection, golden and C, from the detail. `tests/ladx/build/ladx_gen --tables data/ladx tests/ladx/<cases|combos>/<case> tmp/check-e2e/<case>` writes C's `run.txt` to diff against the golden's (ROM-free: no `--rom`). Placement lines are `place`, draws are `trace` lines (`<n> <generator> <args> <stage> <result> <words>`; the 4th field is LADXR's `<module>:<qualname>`).
  - LADX, a write-log failure (`<group>: line <n>:`, `trace <group>: line <n>:`): the group, the projection line number and the detail's golden and C lines. Without the ROM, `python3 -I tests/ladx/oracle/write_log.py project <rom_writes.txt> <group>` on the golden and on C's log gives the projections the driver compared. Under `e2e-rom`, only the redacted detail (`B <offset> (<k> tokens)`); C's log stays unprinted.
  - LADX, `spoiler:` or `net:`: the detail line (digests, offsets and kinds only).

  The case's `config.json` (ALttP) or `config.txt` (LADX, its non-default settings) says which option it exercises.
- **Constraints on the fix**, to be carried into every stage:
  - The RED test is a **unit test run by `make -C <game> test`** (see "Where the RED test goes"). Never a new case in `<game>/cases/` or `<game>/combos/`.
  - Its cost is **negligible**: it builds the minimal state that reaches the cause, it does not run a whole generation, it reads no file of `<game>/cases/`, `<game>/combos/`, `tmp/` or the ROM, and it runs well under 50 ms. Needing a full seed to go red is the sign the real cause has not been found — go back to diagnosis, don't ship it.
  - The fix turns the new test and the gate's commands (step 4) green.
  - A divergence is a bug. Never regenerate or edit a golden by hand.
  - LADX: the rules of "ROM safety" above.
- **Already eliminated**, on a retry (step 5): every hypothesis the previous attempts disproved, and why their commit was refused.

### Where the RED test goes

- **ALttP**: `tests/alttp/unit/test_<module>.c`, registered in `tests/alttp/Makefile`'s `UNIT_TESTS`, failing through `unit/support.h`'s `test_fail`. For a write-log failure, a `test_rom_*` unit test: a hand-built world passed to `rando_rom_write` through a recording writer, checking the writes it records. Never a whole golden `rom_writes.txt` read back.
- **LADX**: `tests/ladx/unit/test_<module>.c`, registered in `tests/ladx/Makefile`'s `UNIT_TESTS` (and `SYNTH_TESTS` when it links the synthetic ROM builder `unit/synth_rom.c`, `HOST_TESTS` when it links `ladx/host/`), failing through `tests/ladx/unit/support.h`. Synthetic data only: no golden, no table of `data/ladx/`, no ROM byte.
  - Seed-level: the world setup (`test_world_setup`), the pool (`test_itempool`), the placer (`test_fill`) or the traced generator (`test_rng`, `test_pyrandom`) on a hand-built graph, pool or fixed seed.
  - Write-log: the group's C entry point (`test_<group>`: `test_hints`, `test_items`, …; `test_pipeline` for the order, `test_encoder` or `test_wlog` for the encoding) on a hand-built state and the synthetic ROM, checking the records the write logger holds.

### Where the fix goes (LADX)

When the proven cause is a ROM-derived artifact — a golden, a table of `data/ladx/`, or a Side, Group or coverage of `notes/ladx-inventory.md` — the fix goes into the oracle scripts or `tests/ladx/oracle/ladxr.patch`, never the artifact (`docs/plan-3.md` §2). Its RED test is a `tests/ladx/oracle/test_*.py` run by `make test-ladx-oracle`, and the artifact is regenerated with the ROM in its own commit, the reason and evidence in its message. A scope cut is never the fix.

### 4. The commit gate — check, then accept or refuse
When `fix-bug` proposes its commit, check each point yourself, with commands you run:

1. The diff adds (or extends) a test under `<game>/unit/` and its binary is in that Makefile's `UNIT_TESTS` (or, for an oracle fix, a `tests/ladx/oracle/test_*.py`).
2. That test reads no file of `<game>/cases/` or `<game>/combos/` (nor, for LADX, `data/ladx/`, `tmp/` or the ROM) and runs under 50 ms (time it).
3. It **fails on the pre-fix code**: in a throwaway `git worktree` of `HEAD` under `tmp/`, apply only the diff's `tests/` changes, build and run the test — it must fail. Then it passes on the working tree.
4. Green, and the failure you handed over no longer appears:
   - ALttP: `make -C tests/alttp test`, `e2e` and `e2e-combos`.
   - LADX: `make -C tests/ladx test`, `e2e`, `e2e-combos` and `e2e-synthetic`, and, with the ROM, `e2e-rom` and `make -C tests/ladx rom-check`. A fix that changes C's outputs makes `e2e-synthetic` red on purpose: that is not a refusal; it is committed first, then `make -C tests/ladx synthetic-refs` rewrites `synthetic_refs.txt` in its own commit, only after `e2e-rom` and `rom-check` are green with the ROM.

All four hold → accept: `fix-bug` commits (folded into `HEAD` when `progress.md` exists, see `git-commit`). Remove the worktree.
Any one fails → refuse, with the reason. Nothing is committed; restore the working tree to `HEAD` before the next attempt.

### 5. Count the attempt
An attempt fails when you refuse the commit, or when `fix-bug` stops on its own (cause unproven after two debug agents, verification failing twice).

- Fewer than 3 failed attempts on this failure → back to step 3 with the same failure, the bug report extended with what was eliminated and why the last attempt failed.
- 3 failed attempts → stop. Report `E2E-FAILED:` to the user: the failure, the three attempts, what each eliminated, and which observation is missing. This is the only moment this skill hands back to the human.

### 6. Loop
After an accepted commit, back to step 1: every target from the top.

## The ranker

`python3 .claude/skills/check-e2e/scripts/rank_e2e.py <game> <output>...` reads saved outputs of `<game>`'s targets (each run named after its file name without extension; run order `e2e`, `e2e-combos`, `e2e-rom`, then any other name in argument order) and prints:

- `SETUP <run>: <line>` per `setup:` line, first;
- `rank-e2e: <n> failure(s) in <game> (<runs>)`, then `<i>. <run> <case>: <reason>` per failure in rank order (`(target)` for a target-level one), then `TOP <run> <case>`, the top failure's lines verbatim, and `REPRO <command>`;
- or `rank-e2e: no failure in <game> (<runs>)`.

Exit 0 with no failure and no setup line, 3 with setup lines only, 1 with a failure, 2 on a usage error (an unreadable file, a directory that is not `…/alttp` or `…/ladx`, a missing `order.txt` or `write_groups.txt`).

Ranking, smallest first:

1. **Target-level failures**, in run order: `KS DIFFERENT`, `PROJECTION`, `run_e2e:`/`run_e2e.sh:` errors and `e2e-rom: KS:` generator failures, all of one run as one failure; and a run with no case verdict line (`e2e: <p> pass, <d> divergent…` or `e2e-rom: …`), no `DIVERGENT` and no `setup:` line, i.e. a build or driver failure (`no verdict line`). They block the case verdicts of their target.
2. **`baseline`**, before any other case: the cheapest case to replay.
3. **The class** of the case's cheapest detail line (a case ranks at its smallest):
   - LADX: (a) **seed-level** — a generator failure (`no C generator`, `c generator exited|timed out`, `c wrote no run.txt`, `c run.txt malformed`) first, then any `<section>: line <n>:` whose section is not a write-log group (the stage projection: `ws`, `pool`, `place`, the fill's `trace`, …), by `n`; (b) **the write log** — `c wrote no rom_writes.txt` and `c rom_writes.txt malformed` first, then each group at its first row in `data/ladx/order.txt` (the inventory's section order: `generateRom`'s, then `Randomizer.__init__`'s, then `fixHeader`'s), `trace <group>` before `<group>`, then by line number; `spoiler:` at the spoiler's row; a group missing from `order.txt` after the listed ones; (c) `net:` last.
   - ALttP: (a) **seed-level** — any detail not a `rom_writes.txt:` line nor `c wrote no rom_writes.txt`, by the golden trace line's attempt and draw when shown, after every shown draw otherwise; (b) **the write log** by `write_groups.txt` order, then write number; a short (`c ends after <k> writes`) or missing log ranks at the golden's write `k + 1` (write 1), grouped by that golden line's tag.
4. Run order, then case name.

`REPRO`: LADX `make -C tests/ladx <e2e|e2e-combos> CASES=<case>`; under `e2e-rom`, `python3 -I -B tests/ladx/run_e2e.py --rom tmp/ladx/base.gbc --no-ks --cases tests/ladx/<cases|combos> --gen tests/ladx/build/ladx_gen --tables data/ladx <case>`; a `PROJECTION` line, the driver's `--projections` on its case; any other target-level failure, `make -C <game> <run>`. ALttP: `tests/alttp/run_e2e.sh <case>`, or `RANDO_CASES=tests/alttp/combos RANDO_CLAIMS=tests/alttp/combo_claims.txt tests/alttp/run_e2e.sh <case>` for `combos/`.

Self-test: `.claude/skills/check-e2e/tests/`, run by `make test-template` (part of `make test`).

## Output

- `E2E-GREEN:` + the `fix:` commits made, or folded into `HEAD` (possibly none), and, for LADX, whether `e2e-rom` ran.
- `E2E-FAILED:` + the report of step 5. The working tree is back at `HEAD`, nothing half-fixed is left behind.

Never push: the caller decides.
